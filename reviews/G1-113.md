## Engineering findings

The tranche supplies boundaries for all five arms:

- Ordinary and portfolio attempts preregister before model observation, bind observations to the registered dispatch, preserve exact request/response artifacts, invoke Lean for answered outputs, and emit typed cost traces.
- Product-only requests freeze the exact visible unverified products and retry link. Intermediate products remain unverified and cannot be reclassified from empty `NO_ANSWER` responses.
- Multi-fidelity requests bind stage identity, rank, retry, and an empty product set.
- Verified-chain products use a fixed Lean-comment discriminator followed by exact Lean bytes. The signed bytes are the bytes passed to Lean and named by the verifier receipt.
- `AdmittedProduct` requires a PASS receipt, dispatch-authority authentication, same-cell validation, and matching host execution-ledger evidence.
- Retry links carry an eligible signed predecessor completion. Registered-only, signed-but-unexecuted, forged, PASS, off-ledger, wrong-cell, and non-earlier predecessors are rejected.
- Missing telemetry stays unknown rather than becoming zero. An incomplete five-arm cohort yields `INCOMPLETE`, never PASS or FAIL.

Review iterations closed cross-manifest completion substitution; cross-dispatch observation replay; product emission from an `ERROR` observation; producer substitution; forged or unverified signatures; `PRODUCT`/`NO_ANSWER` reclassification; JSON-envelope versus Lean-byte mismatch; cross-split/runtime/budget reuse; duplicate product visibility; failed-verifier leakage; attempt-number-only retry; phantom completion retry; off-executor fake PASS evidence; and a shallow retry test that did not reach the ledger gate.

G1-111 also exercises validation-to-test leakage, hidden unverified visibility, preregistration ordering, wrong-runtime reuse, missing cost telemetry, and partial five-arm cohorts across the integrated seams.

## Trusted-host boundary

These guarantees assume a trusted execution host:

- `model_call` and `verifier_call` are trusted ports; repository code cannot prove that a malicious same-process host contacted the intended model or Lean runtime.
- The HMAC ledger protects evidence only while its database path and secret stay host-controlled. Python privacy is not a same-process security boundary.
- Scheduled-chat hidden reasoning, provider routing, cached state, accelerator work, energy, and authoritative token counts can remain unobservable.
- The host must enforce fresh task state, frozen model/product identity, isolation, timeouts, and durable dispatch/ledger retention.
- Out-of-band calls that bypass preregistration are outside dispatch authority.
- Shared serving or concurrency can interfere unless prospectively controlled.

Therefore `visible_utf8_bytes` supports only a matched observable-budget claim, not provider-token or physical-compute equality.

## Scientific blockers

1. `goal1/GOAL1.json` remains `DRY_RUN`, with benchmark `UNSELECTED`/`UNPINNED`/`UNLOCKED`, `cost_model_frozen=false`, and `model_usage_basis=UNFROZEN`. The benchmark lock is not yet adopted by the active experiment authority.
2. The confirmatory problem manifest, protected split, identities or cluster rule, prompts, arm deltas, seeds, retry limits, terminal-outcome rule, and one-shot analysis input are not frozen as one content-addressed contract.
3. Complete-cost policy still needs prospective choices for model identity, observable basis, residual budget, cancellation/missing output, verifier/orchestration host classes, shared work, concurrency, and hidden-compute sensitivity.
4. No deployment-host runtime preflight or real assembled five-arm cohort has completed.
5. The evaluator accepts caller-created `OutcomeRecord` values without an authority-backed join to benchmark root, artifacts, runtime, verifier receipt, closed dispatch, execution ledger, and cost evidence.
6. Scientific inference needs one admissible outcome for every frozen problem in all five arms. Missing cells cannot become losses, complete-case exclusions, or replacements.
7. Pilot data is non-credit and may inform only the preregistered discordance-based power update. It may not select confirmatory problems, prompts, arms, direction, or target.
8. Confirmatory success requires all four directional paired contrasts, exact McNemar tests, Holm correction, effect sizes, and the single prospective analysis invocation.

## Verdict
